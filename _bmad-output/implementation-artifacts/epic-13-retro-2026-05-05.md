## Challenges

### 1. Story 13.4 v1 fiasco — the headline failure

**Two long expensive runs.** v1's three-anti-pattern stack:
1. Shared `include_buffer` clobbered parents across nesting levels
2. Band-aid response: `chain_walk_decide_hack` / `chain_walk_apply_hack` / `input_frame_hack_marker` triplet to mask the symptom by setting `tib_in = tib_len` on parent restore
3. Ship-the-band-aid + spawn-substory: the band-aid worked for clean-EOF flows but broke the THROW-caught-by-outer-CATCH path. v1 shipped 8/11 probes and spawned Story 13.4.1 to defer 3 broken probes.

**Caught only in party-mode session post-flush 2026-05-04.** v2 redesigned with Pre-Design Contract PD-1..PD-14 binding: per-FCB 128-byte slab makes parent-clobber **structurally impossible**, not flag-juggled. HALT discipline + identifier gate (banned `hack`/`workaround`/`tmp` substrings in shipped identifiers) + checkbox discipline (parent `[x]` requires every subtask `[x]`).

**v2 byte delta:** +2,058 B vs +1,750..+1,900 envelope — HALT logged, project-lead-accepted as calibration data for future capstone stories.

**Project lead 2026-05-05:** *"13.4 was a fiasco. We had to abandon and completely redo it. Both runs took ages to complete… going smoothly until 13.4 which blew everything up. Then it felt kinda rough from there onwards."*

### 2. F-Retro-1 — In-pass adversarial review kept happening despite codified intent against it

**Root cause is structural, not disciplinary.** Three layers in conflict:
- **Memory** (`feedback_adversarial_review.md`) + **dev-agent definition** (`_bmad/bmm/agents/dev.md:64` — "For best results, use a fresh context and a different quality LLM if available") = codified intent for fresh-context external review only
- **Workflow** (`_bmad/bmm/workflows/bmad-quick-flow/quick-dev/steps/step-05-adversarial-review.md`) = mandates in-pass review as Step 5 with no skip branch; Step 5's `nextStepFile` is hard-coded; failure-mode list literally includes "Accepting zero findings without questioning"
- **Story templates** (every Story 13.x AC says "trigger an adversarial review pass per `feedback_adversarial_review.md`")

**The dev agent followed instructions — the wrong stack.** Workflow-as-runtime won. Intent never made it into the workflow tree.

**Fix:** Story 13.5.0 (PD-1) — edit `step-05-adversarial-review.md` (skip-branch or removal); remove "trigger an adversarial review pass" from create-story AC pattern; reconcile with `CR` command guidance. **Process foundation that gates every subsequent 13.5.x dev-pass.**

### 3. "Pre-existing / out-of-scope" used to discharge correctness defects

**TD-5 — `."` BC-clobber.** Story 13.5's adversarial review classified MEDIUM, accepted-with-rationale because pre-existing. **Project lead 2026-05-05:** *"a clobber like that should never have been passed off as 'pre-existing, so I'll ignore it'."*

**TD-6 — PAD/HERE-cross-line volatility.** Story 13.5's F3 forward-port said "use HERE not PAD"; Story 13.6's F-9 hardware finding revealed that's wrong across REPL lines. Two findings against the same incorrect mental model — initially classified as smoke-batch authoring bug, retroactively re-classified as kernel correctness concern.

**Codified:** `feedback_no_preexisting_discharge.md`. The threshold question — *"would I be embarrassed for the project lead to discover this defect by stepping on it?"* — eliminates the discharge.

### 6. The "losing control of the process" feeling

**Project lead 2026-05-05:** *"epic 13 doesn't feel that big ('add FS support!') and it was all going smoothly until 13.4 which blew everything up. Then it felt kinda rough from there onwards TBH. ## Key Insights

| # | Lesson | Why it matters |
|---|--------|----------------|
| **13-A** | **Codified intent loses to workflow-as-runtime when they conflict.** | If memory or party-mode says "stop X" and the BMAD workflow tree still requires X as a step, X happens. The fix lives in workflow files + templates, not in memory or instructions. |
| **13-B** | **"Pre-existing" is never a discharge for correctness defects.** | Codified as `feedback_no_preexisting_discharge.md`. Retroactively re-classifies TD-5 / TD-6 upward to tag-blocking. |
| **13-C** | **Capstone-shape stories need different drafting discipline than leaf stories.** | Leaf stories with one focused thing draft accurately; capstone stories with infrastructure + multiple words + tests systematically under-spec. Sum-of-parts itemisation with DEFCODE-header overhead per word. |
| **13-D** | **One-anti-pattern can poison the rest of an epic; process-recovery overhead is real.** | Story 13.4 v1's failure didn't only cost 13.4 — it added process gates that amplified perceived cost across 13.5 / 13.6 even though those stories were structurally clean. Worth budgeting. |
| **13-E** | **Verdict-only audit pattern handles blast-radius investigations correctly.** | Hypothesis at Story 13.5 party-mode was off by 4 orders of magnitude; the probe-in-tree captured ground truth before the fix. `feedback_verdict_only_audit.md` extended. |
| **13-F** | **Mid-epic hardware-smoke cadence is load-bearing, not optional.** | Easy to skip story-by-story; cost compounded at the close-out gate. Three hardware runs at 13.6 each ate project-lead time. Codified as standing commitment S9. |
