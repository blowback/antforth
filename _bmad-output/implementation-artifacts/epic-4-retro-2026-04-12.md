## Challenges

### 1. Register-Contract Violations (Dominant Bug Class)

Appeared in 4 out of 6 stories (4.1, 4.2, 4.3, 4.4). Every time a new helper call or dispatch path was added, DE (IP) or BC (TOS) got clobbered. Examples:
- Story 4.1: NEXT, used DE as copy destination (clobbered IP); arithmetic helper passed base opcode in D (clobbered IP high byte)
- Story 4.2: `LD DE, (asm_body_start)` ran before DE save prologue; END-CODE didn't preserve DE/BC across helper calls; JR,/FIX/DW, used D/E as scratch
- Story 4.3: Various HL clobbering in 16-bit immediate paths
- Story 4.4: asm_emit_byte HL clobbering affected CB-shift and OUT r-field generation

**Resolution:** Interactive smoke testing caught every instance. By Story 4.4, the team had established the pattern of spilling DE to `asm_ip_save` first in every new opcode word. Automated REPL tests alone would NOT have caught these.

### 2. Tag Encoding Grew Organically (Should Have Been Designed Up Front)

Story 4.1 used raw register indices (high byte zero). Story 4.3 bolted on `0xFD` for immediates and `0xFE` for conditions. By Story 4.3, bare integer `0` was indistinguishable from register B, creating a silent-misassembly footgun. Required a mid-epic refactor (Story 4.3.5) to unify all tags under `0xFF` class/index encoding.

**Root cause:** The full universe of operand types (registers, conditions, immediates, labels, indirect modes) was known from the epic spec, but the encoding wasn't designed to accommodate them all from the start.

**Resolution:** Story 4.3.5 delivered the unified encoding. The refactor was painful but produced a cleaner, safer architecture that simplified all subsequent dispatch code.

### 3. Operand-Order Inconsistency (Story 4.3 Showstopper)

Immediate-form `LD,` read `value # dst LD,` (src-first) while register-form read `dst src LD,` (dst-first, Zilog convention). Inconsistency caught during adversarial code review after story was initially marked done.

**Resolution:** Full restructure of immediate dispatch. Reverted status to in-progress, restructured to detect marker on TOS, unified to Zilog dst-src across all forms. The fix was cleaner than the original.

### 4. ED Misc Opcodes Missing from Story 4.4 Spec

NEG, RETN, RETI, IM 0/1/2, and block I/O instructions were not listed in the 4.4 acceptance criteria. Project lead had to prompt for them before development.

**Root cause:** Story spec enumerated instruction categories from memory rather than systematically cross-referencing the Z80 manual. An entire well-known table fell through the cracks.

### 5. Scratch Slot Proliferation

By Story 4.4, the assembler had 5 separate spill slots (`asm_tmp`, `asm_tmp2`, `asm_ip_save`, `asm_resolve_target`, `asm_jp_op`) with implicit no-nesting invariants. Manageable but adds cognitive load.

---

## Key Insights

1. **Design foundational encodings for full scope up front** — When a data representation will be extended in later stories, design for all known future types on day one, even if only a subset is implemented immediately. Thirty minutes of up-front design would have prevented Story 4.3.5.
2. **"The manual is the checklist"** — When the scope is a complete instruction set, cross-reference the authoritative hardware reference systematically. Memory-based enumeration misses categories.
3. **Interactive smoke testing is essential for register-contract code** — Automated tests alone miss IP/TOS corruption. This was the dominant bug class. Run CODE words interactively before trusting the test suite.
4. **Mid-epic refactors can be net positive** — Story 4.3.5 was unplanned but delivered a cleaner, safer architecture that reduced implementation cost for Story 4.4. Committing fully to the refactor rather than patching was the right call.
5. **Rejecting clever designs pays off** — The label system explicitly rejected INTERPRET hooks and sigil syntax in favour of explicit `LABEL`/`FIX`. Result: zero changes to outer_interpreter.asm, structural typo guards, best-in-class usability.
