## Dev Notes

### Bug summary (per current investigation)

The reproducer `: T58 S" ( unterminated " EVALUATE ; ' T58 CATCH . CR DEPTH .` confirms the F8 defect. Observed mechanism (verified via source-read but NOT via debugger trace; dev agent re-verifies in Task 2):

1. `T58` runs. `S"` pushes `c-addr u` for the literal `( unterminated ` (length 16).
2. EVALUATE is called. `(SAVE-INPUT)` pushes 4 cells (`source_id=0`, `tib_in`, `tib_len`, `tib_addr`) onto the IX rstack — call this the **source-frame**. EVALUATE then installs the new source: `tib_addr=eval-string`, `tib_len=16`, `tib_in=0`, `source_id=-1`.
3. EVALUATE calls `INTERPRET` (nested).
4. The nested `INTERPRET` calls `WORD` to parse the next token. `WORD` returns `(`. INTERPRET dispatches to `w_PAREN_cf`.
5. `w_PAREN_cf` (`src/strings.asm:908-969`) computes `BC = tib_len - tib_in = 14` (or so, depending on what `WORD` advanced `tib_in` to), scans for `)`, exhausts BC without finding `)`, branches to `.paren_missing`, and raises `THROW_END_OF_INPUT (-58)` via `JP w_THROW_cf.kernel_entry`.
6. `w_THROW_cf.kernel_entry` (`src/exception.asm:317-394`) finds the wrapping CATCH frame (the `' T58 CATCH` frame), restores SP from frame +0, restores catching-IP from frame +4, restores CATCH-TOP from frame +6, and pops the 8-byte CATCH frame via `ADD IX, BC` with `BC=8`. **The 8-byte (4-cell) source-frame between the CATCH frame and the THROW site is implicitly discarded by IX advance — its contents are not restored to the USER area.**
7. CATCH's caller resumes. `tib_addr=eval-string`, `tib_len=16`, `tib_in=16` (or wherever `(` left it — likely at end-of-source since the `.paren_scan` loop advances `tib_in` per char read), `source_id=-1`. `-58` is on the data stack (per `w_THROW_cf.kernel_entry` `LD BC, (throw_saved_n)` at `:390`).
8. The OUTER `INTERPRET` (the one wrapping the user's REPL line `' T58 CATCH . CR DEPTH .`) continues parsing for its next token after the `CATCH`. It calls `WORD` to get `.`. **But `WORD` reads from `tib_addr+tib_in` of the CURRENT (still-EVALUATE) source-frame** — at end-of-source. `WORD` returns empty.
9. The outer INTERPRET sees empty token, exits to QUIT. `.`, `CR`, `DEPTH`, `.` are NEVER executed (this is what F8 means by "swallowed").
10. QUIT prints ` ok` and loops back to `QUERY`.
11. `QUERY` (`src/outer_interpreter.asm:103-136`) reads the next REPL line into `bdos_input_buf`, sets `tib_len = new-length`, `tib_in = 0`. **But `QUERY` does NOT reset `tib_addr`** — `tib_addr` still points at EVALUATE's `eval-string` literal (which lives in T58's compiled colon body in dictionary memory).
12. Outer INTERPRET parses the new line *from the EVALUATE buffer* — re-reads `( unt...` again, runs `(`, exhausts source, raises `-58` again. Hence the F8 description "the `-58` only fires when a subsequent line is parsed".

### Fix locus

The AC author's "fix in `w_PAREN_cf`" framing originated from the Story 11.6 F8 author's diagnosis that `(` was reading past EVALUATE's source. The investigation above shows `(` is correctly bounded; the actual fault is in source-frame restoration on THROW unwinding (a structural gap that Epic-13's `INCLUDE-TOP` chain will eventually fix at the architectural level — see `architecture.md:166-191` CCD-1 for the planned mechanism). For Epic 11.5's stabilisation-interlude scope, a localized fix is appropriate. AC #3 lists four candidate options; the recommendation is (b)+(c) hybrid:

### Architecture context

EVALUATE's source-frame is currently *unchained* — it lives on the IX rstack but is not linked into either chain. Epic 13's `INCLUDE-TOP` mechanism could subsume EVALUATE's source-frame, but that's out of scope here. - **EXX-Convention** (per Stories 7-8 and `architecture.md` §EXX-Convention): `w_PAREN_cf` is a shadow-using word (enters via `EXX`, exits via `EXX` on both paths). `w_QUERY_cf`, `w_EVALUATE_body`, `(SAVE-INPUT)`, `(RESTORE-INPUT)` are primary-set-only. Conclusion: source-spec restoration on THROW unwinding is a quality-of-implementation choice, not a standards mandate; the antforth project's "investigate before defending" discipline (`feedback_standards_compliance.md`) calls for the structurally-correct fix regardless.

The AC's literal "fix in `w_PAREN_cf`" framing was therefore structurally wrong — the fix belongs at the source-frame layer.

**Task 3 — Fix locus and design (AC #3, #11):**

**Chosen approach: option (b)+(c) hybrid (matches AC #3 recommendation).**

**Option (a) rejected:** "fix in `w_PAREN_cf` (rstack walk to find/restore EVALUATE frame)" is structurally wrong. `(` is one of many words that can run when an EVALUATE source-frame is live: any word that itself raises THROW (e.g., CREATE -16, asm-error -258..-271, runaway colon body -3, divisor zero -10) would exhibit the same defect.
