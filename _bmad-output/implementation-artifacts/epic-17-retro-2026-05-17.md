### 4. Hardware-vs-spec divergence on BANK-MAPPING-OFF caught and fixed-as-bug, not papered over

Story 17.1's first hardware run (transcript 193026) surfaced that `BANK-MAPPING-OFF` triggered a full firmware cold-boot. Root cause: `OUT (0x74), A` disconnects RAM from running code at the next instruction-fetch, falling into the firmware reset path. PRD FR-P4-12 wording ("disables the MMU mapping hardware") was wrong — what the word actually has to do (and the only useful semantics on real hardware where you can't observe anything after disabling RAM) is trigger CP/M warm-boot escape via the BIOS WBOOT vector. Per `feedback_no_accept_disposition_for_bugs.md` STRONG rule, the divergence was treated as a bug, not an "accept + update wording" disposition: PRD + `epics-phase4-...md` + `docs/antforth-banking-redesign.md` wording all fixed in 17.1 CR H1 cascade; implementation switched from `OUT (0x74), A` to `JP $0000` (BIOS WBOOT). Run 2 confirmed `B>` directly post-`BANK-MAPPING-OFF`.

### 5. DE/IP clobber pattern caught early then re-applied with discipline

Story 17.2 CR H1 found that the `BANK!` swap clobbered DE (= inner-interpreter IP) via `EX DE, HL` + `LDIR` cascades without restoring. Bug was hidden because `bank_count = 0` at Story 17.2 close meant every `BANK!` aborted at the precondition before reaching the swap; would have surfaced as a kernel crash on the first `1 BANK!` after Story 17.3's `+BANK` populated the active list. Story 17.2 CR also named the `src/wordlists.asm:48-49` precedent (`PUSH DE ; save IP — LDIR clobbers DE`) it had missed. Once named, the pattern carried: Story 17.3 caught the same shape in `+BANK` (probe scratch clobber) and `-BANK` (LDIR clobber) during dev-pass on the first colon-definition probe run, both fixed via the same `PUSH DE` / `POP DE` wrap. Story 17.4's `cl_probe_and_add` helper was authored DE-preserving from the start because the convention was now top-of-mind.

### 7. bank-table[1..28] LDIR-clone fix caught by real hardware before damage compounded

Captured in `project_bank_table_clone_at_cold.md` memory. **Caught only by hardware** — `make test-repl-banking` had passed because probes don't follow `BANK!` with a `WORD`-parsing operation in the broken bank's context (see Lesson 17-C).

### 4. Hardware-smoke recipe authoring on Story 17.6 ate three round-trips before PASS

First-pass recipe (typed-form `' NEGATE HERE 3 MOVE 3 ALLOT` with WORD-parsing intermixed) clobbered the JP DOCOL prefix mid-recipe — broken on BOTH iz-cpm-banking AND real hardware. Root cause: `WORD` writes counted-strings at HERE+0 before tokens execute; the `3` parsed for `ALLOT` wrote `[01 33]` at start-addr..start-addr+1, clobbering the JP opcode that `MOVE` just placed. EXECUTE then ran garbage Z80 → eventual `JP $0000` (or WBOOT trigger) → warm-boot. **NOT a hardware-vs-emulator divergence** (the dev-pass reproduced it under iz-cpm-banking before re-attempting hardware; per `feedback_no_accept_disposition_for_bugs.md` discipline, the initial mis-diagnosis as real-MB-only was rejected). Corrected recipe wrapped the body in a one-line colon definition with `[']` (compile-time XT resolution). **Second attempt failed via user typo** mid-line (`OVER 3 MOVE 3 ALLOT` has two `3` digits close together; user dropped `MOVE 3 `). **Third attempt** decomposed to 5 short helper words (each independently verifiable, typo-recoverable) — PASSed first try (`TTT . → 12345 ok` on real MicroBeast, transcript 095237). **Lesson:** hand-typed hardware-smoke recipes for hand-built memory-write probes are brittle in ways colon-body PASS evidence doesn't expose. Two robust shapes: (a) smoke-test the recipe under iz-cpm-banking in its EXACT typed form before handing off; (b) decompose to short helper words.

### 5. bank-table[0] LDIR-clone defect caught only by real hardware

Story 17.4's `make test-repl-banking` passed cleanly with the original `bank-table[]` zero-init (no LDIR-clone). The defect surfaced only on Story 17.4's first hardware run because real hardware preserves state between user-typed lines — `BANK!` to an unvisited bank loaded HERE=0, then the *next* user-typed line invoked `WORD` (via REPL parsing) and corruption fired. `make test-repl-banking` probes don't reproduce this shape because probes don't follow `BANK!` with a `WORD`-parsing operation in the broken bank's context. **Cost:** caught late in 17.4's CR pass; fix (+11 B LDIR-clone at COLD) shipped same-pass; regression probe `cl-probe-bank-roundtrip` now closes the gap. **Generalised in Lesson 17-C below.**
