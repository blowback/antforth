## Dev Notes

### Why this story exists (context for the dev agent)

Epic 19 shipped the bank-aware compiler **mechanism** (bodies + stubs land correctly; verified via explicit `EXECUTE` on emulator + bank-0/hardware) but the **behavioural** north-star — calling a banked word from a compiled definition — corrupts the kernel, and two prior fix attempts (19.2 H5 +17 B, 19.3 CREATE +33 B) had to be REVERTED not because the fixes were wrong but because an unexplained trampoline hang made them unverifiable. This story buys the epic its footing: explain the hang (DR-1), then choose the rework architecture (DR-2). Nothing else in Epic 19.5 can move until both are locked.

### The two dispatch root causes (verified citations, re-checked at draft time on commit 94c2ba0)

- **(a) DTC threading through stub-xt.** `NEXTHL` (`src/macros.asm:39..47`): `LD E,(HL) / INC HL / LD D,(HL) / INC HL / EX DE,HL / JP (HL)` — a blind jump to the fetched thread cell. A banked word's thread cell is a descriptor-stub xt whose byte 0 = `target_bank` (e.g. `$05` = `DEC B`) — the CPU decodes data as opcodes and falls into the stub's `JP target_addr` (byte 1 = `$C3`) WITHOUT the MMU swap + frame push that `w_EXECUTE_cf`'s 3-way dispatch (`src/inner_interpreter.asm:386..463`) performs. Note Story 18.3 CR-H1 (comment at :443..453): the in-stub `JP` at stub+1 is DEAD CODE on the EXECUTE path (dispatch reads bytes 2..3 directly so DOCOL sees HL = CF) — but it is exactly what a blind `NEXT` falls into. Any DR-2 option must preserve the DOCOL `HL = CF` precondition (`body = HL+3`).
- **(b) Trampoline assumes DOCOL/EXIT pair.** `w_EXECUTE_cf.cross_bank` (:404..441) pushes a 3-cell frame (caller_bank, xt-of-EXIT, caller_IP) and pre-loads `DE = cross_bank_return` so the *callee's DOCOL push of DE* provides the sentinel cell; `EXIT_CODE` (`src/inner_interpreter.asm:55..70`) pops and compares against the 16-bit constant; the trampoline (`src/banking.asm:1132..1148`) restores MMU + `current_bank` and jumps on. DOVAR/DOCON/code-word targets never push DE and never EXIT → the frame is dereferenced as thread cells → hang (Probe-19.3-F, deferred in `tests/banking_tests_19_3.fth`).

### Hypothesis seed for DR-1 (Task 1) — including draft-time counter-evidence

The fragility record (`feedback_iz_cpm_trampoline_fragility` memory; H5 revert note at `src/antforth.asm:198..213`): hangs at +17 B (19.2 H5) and +33 B (19.3) growth near the 26726 B baseline; 100% reproducible per layout; cold_start NOP padding (+0..+128 tried) does NOT recover.

**Draft-time observation the dev-pass MUST weigh:** the kernel has since moved 26726 → 26886 (19.3.1) → 26834 (19.4 CR fixes, −52 B with code inserted AND deleted across `file_access.asm`/`banking-adjacent` regions), and the FULL banking sweep passes at 26834 (61/0 + all isolated suites, including probe-18.2-a and the iron-spike). So the defect is NOT a monotonic size threshold — specific layouts hang, others of larger/smaller size pass. This is consistent with:

- **H-A — sentinel value-collision (seeded as primary).** `EXIT_CODE` discriminates cross-bank returns BY VALUE: any legitimate popped return address numerically equal to `cross_bank_return`'s current address falsely enters the trampoline, which pops two cells that aren't a frame and `JP`s wild → hang. Why uniform NOP-padding wouldn't recover: padding shifts `cross_bank_return` AND any colliding code-derived IP label by the same delta, preserving the equality; only RELATIVE shifts between the two symbols (i.e. growth located between them) break or create collisions — matching the observed "+17 B here hangs, +125 B there is fine" pattern. Sub-1.2's relative-shift probe is the cheap decisive test. If H-A holds, DR-1's fix space includes: reserve an address for the sentinel that cannot be a legitimate IP (alignment trick / dedicated gap), or replace value-tagging with an explicit frame tag — itemise both.
- **H-B — emulator defect** (the memory's stated belief): iz-cpm-banking (vendored fork of blowback/iz-cpm @ 1777a85, picked Story 16.3) mishandles something the layout shift exposes (page-table edge, instruction straddling a boundary). Q2 allows diagnostic instrumentation of the emulator. If confirmed, severity reframes (hardware likely unaffected) — but per `feedback_no_accept_disposition_for_bugs` still propose the emulator fix, and state the hardware-truth caveat (no HW this story; assumption carried to 19.5.4).
- **H-C — latent antforth frame bug** that only bites at particular address values (high-byte aliasing in the two-byte CP at `EXIT_CODE:60..66`, IX arithmetic at page edges, etc.).

These are seeds, not a closed list — record falsification evidence for whichever are rejected (AC1).

### Task 1 evidence summary (DR-1 root cause)

**Mechanism (named): portal-window dictionary aliasing.** The interpreted-mode dictionary (HERE) grows monotonically from `kernel_end` and, in the full banking_tests.fth sequence, crosses `$8000` — the MMU slot-2 window. A colon body compiled at/above `$8000` physically lives in the page mapped at compile time (bank 0's page `$22`, which is also the boot mapping). When such a body — or any code whose *thread cells / inline-string bytes* at ≥ `$8000` must still be fetched — executes `BANK!` to a foreign bank, the window remaps and the remaining cells alias into the foreign page. The next NEXT fetch reads foreign bytes: zero-filled page → cell `0000` → `JP $0000` → CP/M warm boot (emulator exits); non-zero residue → opcode soup (can spin = the historical "hang" flavor; `$76` HALT residue → emulator halt, demonstrated). No trampoline, no sentinel, no EXECUTE frame, no emulator defect involved.

**Death trace (current baseline, inline iron-spike configuration):** `--cpu-trace` tail shows `(.")` at `$1864` processing the 34-char `iron-spike-sentinel-12345-returned` literal at `$7FE6` (body cells below `$8000` execute fine after `5 BANK!`), IP advances past the string to `$800A`, fetch under bank-5 page `$39` returns `0000`, `JP HL` → `PC=0000` → `JP ff03` (warm boot). Numeric straddle confirmed in-band: HERE before `: _iron-spike-test` = 32580 ($7F44), after `;` = 32866 ($8062); $8000 = 32768 falls mid-body.
