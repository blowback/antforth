## Challenges — and the bigger one

### 1. Sprint-status pre-state drift — 4 stories running, no fix

Same /CR finding in 14.2 / 14.3 / 14.4 / 14.5: the story claimed canonical `ready-for-dev → in-progress → review`; the actual transition was `backlog → review`. The story-template's example boilerplate primed every dev-pass to lie about it. Caught at /CR every time. **The lint we built can't catch the lint-builder's example.** (Lesson 14-D.)

### 2. `_bmad/` is gitignored — 3 structural payloads not in version control

The 14.2 / 14.3 / 14.4 `<critical>` blocks live only in the project lead's working tree by lucky persistence since 2026-05-05 (Story 13.5.0 / PD-1). The BMAD installer manifest doesn't enumerate files within modules. Status quo, not Epic-14-introduced — but Epic 14 made it acute. Three of five Epic 14 deliverables are persistence-by-luck. Project lead's call this retro: **not committing `_bmad/`.** Live with it.

### 3. Recursive-irony pattern is structural, not coincidence

Every B-story's lint caught the drafter who wrote its AC, in-pass:
- 14.1: architecture-doc example used `CMOVE` (a B.4-territory figure-drift moment inside the very story documenting the CMOVE-vs-MOVE lesson)
- 14.2 AC6(d): `<critical>` count off by 14× (16→17, not the spec's 1→2)
- 14.3 AC5(b): markdown-bold regex couldn't match the canonical example
- 14.4: FOUR moments — indent depth, close style, Δ count, sprint-status not in pre-flight list
- 14.5 H1: the regex bug *masked* the Story-cite truncation it was meant to catch

The drafter's mental model is *always* the failure mode the new lint codifies. (Lesson 14-A — but see "Bigger one" below.)

### 4. Story-body bloat unaddressed

14.3 L2 finding: "540 lines for a 7-line template diff — approaching parody." Deferred to this retro. 14.4 partial heed (condensed S1..S12 walk). 14.5 still 742 lines for a tooling story. The "preserve every section per template" instinct overrode every signal.

### 5. **The bigger one: process-foundation has run past its useful return**

Project-lead verdict mid-retro: *"PM ceremony masturbation … getting in the way of actual development."*

Looking honestly at Epic 14's deliverables:
- **14.1 (real onboarding doc)** — should have been one paragraph in `tests/README.md`, not a 26K-token story.
- **14.2 / 14.3 / 14.4 (workflow-tree `<critical>` blocks)** — three notes-to-self codified as deliverables, in a gitignored directory, only firing when the project lead re-runs `create-story`. Each took 500–700 line stories to land 5–15 line text edits. These could have been a single memory file, three lines in a checklist, or — most honestly — nothing, because the project lead is the only drafter and can hold the discipline in his head.
- **14.5 (mechanical sweep tool)** — actually does something. Genuinely useful.

**Ratio: 1 of 5 stories did real work; 1 of 5 was real onboarding doc; 3 of 5 were ceremony for an audience of one.**

The Phase-3 plan as drafted contained more of the same: Epic 15 had `make check-tools` (B.6, tooling-on-tooling), test-numbering hygiene (B.8, cosmetic), and a 10-AC close-out gate story (15.6) that itself was a verdict-table walk over verdict tables. **The process apparatus had become its own consumer.**

## Key Insights

| # | Lesson | Why it matters |
|---|--------|----------------|
| **14-A** | **Process-foundation stories are recursively self-referential — the drafter's mental model is always the failure mode the new lint codifies.** | Every B-story caught its own drafter, in-pass, every time. If a process-foundation story's verdict criterion finds nothing, it isn't sharp enough. (Counter-balance: see 14-F before declaring this a virtue.) |
| **14-B** | **Verdict-criteria that *run* over the planning artefacts beat verdict-criteria that grep for known phrases.** | 14.5 found a real architecture defect by mechanical sweep. 14.1–14.4's grep-shaped verdicts could only catch what someone thought to grep for. Mechanical-sweep tooling scales; grep-for-phrase doesn't. |
| **14-C** | **"Constraint named, not closed" is the new honest-disposition shape for ACs whose literal wording can't be satisfied.** | Born in 14.2 AC7. Cleaner than silent PASS or rationale-handwave. Adopted by 14.3 / 14.4 / 14.5. |
| **14-D** | **Story-template's example boilerplate is itself a figure-drift source.** | 4-of-5 stories lied about sprint-status transitions because the template's example primed it. The infrastructure we build to catch drift is itself drift-prone. |
| **14-E** | **`_bmad/` gitignored makes structural payloads load-bearing on luck.** Project-lead decision this retro: live with it. | Three of Epic 14's deliverables persist by working-tree luck. Not a defect in Epic 14; a structural property of the BMAD installer's module-not-file granularity. |
| **14-F** | **Process foundation has diminishing returns once the process is the only consumer of the process. Solo-dev project, audience-of-one drafter, gitignored deliverables → ceremony exceeds value. STOP BUILDING IT.** | Primary lesson of this retro. Reshapes Phase-3 scope: drop pure-meta stories (15.4 B.6+B.8), demote test/probe/parser-tweak stories to direct commits (15.2 / 15.3), trim close-out gate to a checklist (15.6 → paragraph). Keep only what fixes tangible issues in the actual codebase. |
