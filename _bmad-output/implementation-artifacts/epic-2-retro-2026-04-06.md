## Challenges

### 1. DEPTH/`.S` Standards Compliance Failure (Critical — Process)

The `.S` implementation got TOS-in-register depth calculation wrong. When Ant flagged the issue, the team rationalized the behavior ("all Forths behave like that") instead of checking the standard. Ant had to research comp.lang.forth for the correct solution and force the fix.

**Root cause:** Team defended the implementation rather than investigating the standard. Standards compliance was not treated as non-negotiable.

**Resolution:** Ant provided the correct approach; fix was implemented. TOS-in-register semantics documented in memory system.

### 2. Binary Op Underflow Detection Gap (Critical — Testing)

Story 2.4's stack underflow checks failed to detect the most common underflow case: a single argument to a binary operation (e.g., `+` with one item). Neither dev implementation nor code review caught this.

**Root cause:** Insufficient rigor in testing the underflow detection against real user scenarios. The check protected against completely empty stacks but not the "one argument where two are needed" case.

**Resolution:** Ant flagged the issue; additional REPL tests (13-15) added for cross-category underflow coverage.

### 3. Test Thread Modularisation Not Done (Carryover)

Committed to in Epic 1 retrospective. The monolithic test thread in `antforth.asm` continues to grow (now 62+ characters). A failure early in the thread prevents all subsequent tests from running.

**Resolution:** Escalated to new Story 3.0 — first story in Epic 3, must be completed before Story 3.1.

### 4. Code Review Still Finding Missing Edge-Case Tests (Recurring)

Code reviews found missing test coverage in 3 out of 4 stories:
- Story 2.1: IMMEDIATE FIND test added in review
- Story 2.3: Empty `.S` test added, wrong REPL test fixed in review
- Story 2.4: 3 additional REPL tests added in review

Coverage improved over Epic 1 (edge cases vs whole missing suites) but pattern persists.

---

## Key Insights

1. **Standards compliance is non-negotiable** — when the project lead flags an issue, investigate the standard first. Never rationalize or defend without checking.
2. **TOS-in-register semantics are a first-class architectural constraint** — DEPTH=(sp_base-SP)/2 counts SP cells only, not BC. DEPTH=0 means BC is phantom/invalid. Every word reasoning about stack depth must get this right.
3. **The REPL test infrastructure was the epic's biggest process win** — transformed quality assurance from manual-only to 15 automated integration tests.
4. **The project lead should not be the last line of defense for correctness** — both the DEPTH bug and the underflow gap required project lead intervention.
