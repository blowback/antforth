## Story

As an antforth user calling `READ-FILE` against a file on a real (or simulated) CP/M 2.2 filesystem,
I want a real BDOS read I/O error to surface as a non-zero `ior` (per ANS §11.6.1.2080), distinct from a clean EOF (which correctly returns `ior=0` with `u2 < u1`),
So that file-reading code can branch on `ior` to detect genuine I/O failure (bad sector, hardware fault, future random-access read errors) rather than silently absorbing the failure as if the file simply ended cleanly — and so that `(file-refill)`'s `INCLUDE` / `INCLUDE-FILE` paths can raise `-37 THROW_FILE_IO` (the pre-allocated latent) on real I/O failure rather than truncating the source file silently.

This is the third story in Epic 13.5 (Phase-2 Cleanup Slate) — the process-recovery vehicle that gates `antforth 2.0`. It has zero new feature scope; the AC slate discharges the TD-3 debt named in the Epic 13 retro's Tag-Blocking Slate. The fix shape was pre-scoped at Story 13.2 AC #17(h) approach (i) (helper-layer extension); this story lands that shape and threads the new tri-state signal through the two consumers (`READ-FILE` and `(file-refill)`).

## Severity Re-Statement (BINDING — context for every dev-pass decision)

One compliance defect, currently silent (no THROW, no diagnostic), reachable from any `READ-FILE` call where BDOS F_READ returns `A > 1`:

| TD | Defect | Currently observable? | Current behaviour | Standard-required behaviour |
|----|--------|------------------------|-------------------|----------------------------|
| **TD-3** | `READ-FILE` and `(file-refill)` cannot distinguish clean EOF from BDOS F_READ I/O error | No — CP/M 2.2 BDOS F_READ rarely returns `A > 1` in practice on healthy media; the defect is dormant on iz-cpm and on the MicroBeast's SD-backed filesystem under nominal conditions, but is reachable on damaged media, partial-extent corruption, or any future BDOS variant that surfaces real read errors | All CY=1 returns from `file_byte_read` map to `ior=0` (clean EOF). `(file-refill)` treats F_READ failure as EOF, silently truncating the source file at the first byte that can't be read | `READ-FILE`: `ior=0` AT EOF (with `u2` = bytes-read-before-EOF); `ior` non-zero on I/O error. `(file-refill)`: raise `-37 THROW_FILE_IO` on real I/O error; preserve clean-EOF flag-return (`-1` if any bytes read, `0` on immediate EOF) for the common case |

The fix is **structural** — `file_byte_read`'s flag protocol is the bottleneck; once the helper signals three states (success, clean-EOF, I/O-error), every consumer can wire correctly. The Story-13.2 pragmatic mapping was a band-aid the retro re-classified upward; this story replaces the band-aid with the proper tri-state signal.

**Why the defect is dormant in practice:** CP/M 2.2 BDOS F_READ (function 20) returns `A=0` (success), `A=1` (EOF / record past file end), or `A > 1` (read error — rare; hardware/media-dependent). On iz-cpm's host-filesystem-backed implementation, F_READ effectively never returns `A > 1` (the host kernel reports errors via process-level signals, not by-record). On real MicroBeast hardware, F_READ on SD-card-backed CP/M can in principle return `A > 1` (e.g., bad-block on read), but the firmware as-shipped has not been observed surfacing that path in any Story 13.x hardware run. The structural fix is what the retro mandated; producing a hardware reproducer for a real I/O error path is **not** in scope (and is impractical without a synthetic media-fault injector).

**S8 reminder (codified Lesson 13-B per `feedback_no_preexisting_discharge.md`):** TD-3 may NOT be discharged with "accepted-with-rationale: pre-existing" or "accepted-with-rationale: not observable in practice" — it was named a tag-blocker at the Epic 13 retro 2026-05-05 by project-lead direction. Either it lands cleanly here (option a) or the dev-pass HALTs and surfaces (option b per AC #11). No third option.

## Acceptance Criteria

1. **Given** Story 13.1's `file_byte_read` helper at `src/file_access.asm:682..777` whose flag protocol currently uses `CY=0 / A=byte` for success and `CY=1` (no `A` semantic) for both EOF and I/O error,
   **when** Story 13.5.2 lands,
   **then** the helper's flag protocol is **rewritten** to a tri-state signal:
   - **Success-with-byte:** `CY=0; A=byte` — *unchanged from current behaviour.*
   - **Clean EOF (BDOS F_READ returned `A=1`):** `CY=1; A=0` — distinguishable by `OR A; JR Z` after the call.
   - **I/O error (BDOS F_READ returned `A > 1`):** `CY=1; A` = original BDOS return value (`A != 0`, `A != 1`; specifically `A >= 2`, but the helper passes the raw value through after a `DEC A` so callers see `A = BDOS_return - 1`). Distinguishable by `OR A; JR NZ` after a `JR C`.

   Encoding pick (binding): the `.fbr_eof` tail stashes the BDOS A return into a new scratch byte (`.fbr_err`) before the pos-sentinel update clobbers A; after the sentinel update + `POP DE`, the tail reloads A from scratch and applies `DEC A` so `A=1 (EOF)` → `A=0`, `A=2 (real error)` → `A=1`, etc. `SCF` (carry set) follows. The single-instruction `DEC A` keeps the EOF case at `A=0` (clean discriminant for callers) while preserving the original BDOS error code minus 1 for the I/O-error case (callers that want the raw BDOS code can `INC A` after the discrimination test, but no consumer in this story needs the raw code — both consumers only need the EOF-vs-error split).

   `DEC A` followed by `SCF` is `0x3D 0x37` (2 bytes). The choice of `DEC A` instead of `OR A` keeps `A=0` for the EOF case AND preserves the no-byte CY=1 contract via the explicit `SCF`. Estimated cost (helper layer): +8 code bytes inside `.fbr_eof` + 1 data byte for `.fbr_err` scratch.

   **then** a new 1-byte scratch slot `.fbr_err: DB 0` is added immediately after the existing `.fbr_idx: DB 0` at `src/file_access.asm:777` (the natural sibling). The scratch slot follows the existing helper-private storage idiom — function-level scratch, not a USER variable, not a parallel-array. Estimated cost: +1 data byte.

3. **Given** `w_READ_FILE_cf` at `src/file_access.asm:1795..1844` whose post-call discrimination at line 1822 is `JR C, .rf_eof` and whose `.rf_eof` / `.rf_done` tails currently assert `ior = 0` unconditionally,
   **when** Story 13.5.2 lands,
   **then** the consumer is rewired to honour the helper's new tri-state signal. The rewrite shape (binding):
   - The post-`file_byte_read` discrimination becomes a two-stage test: `JR C, .rf_no_byte` (split point unchanged in name; the tail discriminates further). At `.rf_no_byte`: `OR A; JR Z, .rf_eof` (A=0 → clean EOF) — falls through to an I/O-error tail (A != 0 → real error).
   - The I/O-error tail maps `A` → `BC` as the user-visible `ior`. Mirror `w_WRITE_FILE_cf`'s `.wf_io_err` shape at `src/file_access.asm:1901..1910`: `LD C, A; LD B, 0; CP 0xFF; JR NZ, .rf_io_err_done; LD B, 0xFF; .rf_io_err_done: ...`. Sign-extension of `0xFF → 0xFFFF (-1)` matches the existing CLOSE-FILE / WRITE-FILE convention (Code Review L5 in Story 13.2). The I/O-error tail then joins the existing `.rf_done` tail (push `u2` from `fac_done`, NEXT) — `BC` is set above, so `.rf_done`'s `LD BC, 0` becomes the EOF-only assignment.
   - The clean-EOF tail (`.rf_eof`) explicitly sets `BC = 0` and joins `.rf_done`. The success-loop-exhaust path (count exhausted) also lands at `.rf_done` with `BC = 0` already set.

   Restructured tail layout (rough shape — exact labels dev-pass-determined):
   ```
   .rf_no_byte:
           OR      A
           JR      Z, .rf_eof              ; A=0 → clean EOF
           ; A != 0 → I/O error; A holds (BDOS_return - 1) per AC #1
           LD      C, A
           LD      B, 0
           CP      0xFF
           JR      NZ, .rf_done
           LD      B, 0xFF
           JR      .rf_done                ; share the u2-push tail
   .rf_eof:
           LD      BC, 0                   ; ior = 0 (clean EOF)
   .rf_done:
           LD      HL, (fac_done)
           PUSH    HL                      ; u2
           LD      DE, (fac_ip)
           NEXT
   ```

   The count-exhausted path at `.rf_loop` (line 1818: `JR Z, .rf_done`) also needs `BC = 0` — either move the `LD BC, 0` to land BEFORE `.rf_done` on the count-exhaust path (e.g., add a small `.rf_done_ok: LD BC, 0; JR .rf_done` step), OR preset `BC = 0` once at function entry before the loop and only overwrite on the I/O-error path (more byte-cheap; recommended). Pick documented in Completion Notes Task 3 with rationale. Estimated cost: ~15 code bytes.

## Dev Notes

### Why Story 13.5.2 is the natural pick after 13.5.1

Per `epics.md:1702`: 13.5.1..13.5.5 may run in any order. 13.5.2 was picked third (after 13.5.0 process foundation and 13.5.1 dirty-flag) because:

1. **Same-file surface as 13.5.1** — both stories edit `src/file_access.asm`. Landing 13.5.2 immediately after 13.5.1 keeps the file-access surgery sequenced; switching to TD-5 (`."` BC-clobber, `src/strings.asm`) or TD-6 (`PAD` / `HERE`, `src/dictionary.asm`) costs a context switch.
2. **Helper-layer-clean** — TD-3 is contained inside `file_byte_read`'s tail and two consumer call-sites. No data-region growth (just one scratch byte). Predictable byte budget; predictable test surface.
3. **Closes a documented spec deviation** — Story 13.2 AC #17(h) was the "we know this is wrong, we're shipping the band-aid anyway" wart on the user-facing wordset. Closing it brings antforth in line with ANS §11.6.1.2080's explicit error-vs-EOF discrimination requirement.
4. **Closes the latent THROW_FILE_IO -37 slot** — `src/constants.asm:88..89` carries the latent disclaimer. Lighting it up retires the latent.

### Why the helper-layer tri-state signal beats the consumer-side workaround

Story 13.2 AC #17(h) listed two approaches:

- **(i) Extend the helper layer to differentiate EOF vs error** — what Story 13.5.2 lands.
- **(ii) Re-issue F_READ at the user-facing layer to recover the BDOS A return** — rejected at Story 13.2 close because re-issuing F_READ on a transient I/O error is itself a side-effect-bearing operation; the re-issue might succeed (masking the original error) or fail differently (compounding the diagnostic problem). Approach (ii) was discarded at Story 13.2.

Approach (i) is structural — the helper sits at the only call-site where BDOS A is observable; passing the value up via `A` (with `CY` as the success/no-byte discriminant) is byte-cheap (~8 bytes in the helper) and non-invasive at the consumer side (each consumer adds ~10 bytes of post-CY discrimination).

### Why `DEC A` instead of `OR A` in `.fbr_eof`'s tail

The encoding `CY=1, A=0` (clean EOF) vs `CY=1, A != 0` (I/O error) is the cleanest discriminant. The natural BDOS return is `A=1` (EOF) vs `A > 1` (error); the helper applies `DEC A` to map BDOS-1 → 0 and BDOS-N (N>1) → N-1. Three reasons:

1. **A=0 is the discriminator.** Callers read `A` after `JR C, .no_byte`; the natural Z-flag test is `OR A; JR Z, .clean_eof`. Mapping BDOS-1 → 0 makes EOF the Z-set case.
2. **Fewest instructions.** `DEC A; SCF; RET` is 3 bytes (`0x3D 0x37 0xC9`); `XOR A; OR A; SCF; RET` (using a flag-only encoding) is 4 bytes; conditional-jump encodings are 4+ bytes.
3. **Information-preserving.** The original BDOS code is recoverable via `INC A` in the consumer if needed (no consumer in this story does, but the option exists).

The `DEC A` does NOT clear CY — `SCF` after `DEC A` re-asserts it. Important: DEC A modifies S/Z/H/V/N flags but **not** CY. The order `DEC A; SCF; RET` is correct.

### Why `(file-refill)` raises `-37 THROW` rather than returning a different flag

`(file-refill)`'s contract is `( -- flag )` where `flag = -1` if any bytes were read in the line and `flag = 0` on immediate EOF. The contract has no in-band error return — adding a "negative non-(-1) flag = error" channel would break every existing caller that switches on the boolean.

The clean route is THROW. `(file-refill)` is wrapped by `(refill-and-interpret-loop)` which is wrapped by `INCLUDED` / `INCLUDE-FILE`'s `CATCH` (Story 13.4 v2). A `-37 THROW` at the byte-read site propagates up to the CATCH frame, which restores the input source frame and rethrows or surfaces depending on the caller's policy. The user-visible behaviour: `INCLUDE` against a corrupted source file aborts cleanly with a `THROW_FILE_IO` error message rather than truncating the source and continuing as if everything were fine.

### CP/M 2.2 BDOS F_READ behaviour reminder

CP/M 2.2 BDOS function 20 (F_READ) is the underlying read primitive. Per the CP/M 2.2 Interface Guide §5.5:
- A=0: success — DMA buffer contains the next sequential record's bytes.
- A=1: end-of-file (the FCB's CR/EX advanced past the file's allocated extent).
- A=2..255: read error — typically "reading unwritten data" (allocated but unwritten record), media error, or directory error. Rare on healthy media; common on corrupted media or partial-extent FCBs.

iz-cpm's host-filesystem-backed implementation effectively never returns A > 1 (host-kernel errors are reported via process signals or open-time failures, not by-record). Real MicroBeast firmware on SD-backed CP/M can return A > 1 on bad-block reads — but the path has not been observed in any Story 13.x hardware run. The Story 13.5.2 fix is structural — the helper signals correctly when the path fires; consumers route correctly to `ior` or `THROW`. Whether the path fires in field use is a function of media health, not antforth firmware.

### Register-convention pick

The new `file_byte_read` tail operations stay in primary-set context (no EXX). They follow the same register clobber contract as the pre-13.5.2 helper:
- `file_byte_read`: preserves DE (caller's FCB ptr) via PUSH DE / POP DE; clobbers A, BC, HL, F. The `.fbr_err` stash and reload happen inside the existing envelope; CY is set explicitly via SCF; A on return is the discriminant. **Net contract change:** the helper now provides MORE information on no-byte returns (A semantic instead of don't-care). Callers are responsible for honouring the tri-state if they want to distinguish; old callers that ignore A on CY=1 still work (they just lose the EOF/error split).
- `w_READ_FILE_cf`: clobbers BC, DE, HL, A, F (unchanged). The new `.rf_no_byte` arm reads A only; the I/O-error encoder sets BC.
- `(file-refill)`: clobbers per the existing contract (A, BC, DE, HL, F). The new `.fr_loop_no_byte` / `.fr_trunc_no_byte` arms read A only; the `.fr_io_error` arm pops BC and jumps to `w_THROW_cf.kernel_entry`.
