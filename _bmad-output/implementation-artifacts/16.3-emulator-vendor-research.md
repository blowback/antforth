**Author:** Story 16.3 dev-pass, 2026-05-13

## 1. Scope and three pinned criteria

Three eval criteria, verbatim from `docs/antforth-banking-redesign.md` §9 item 2 (line `:168`), `prd.md:168` (PD-P4-9), and `architecture.md:496` (three-test-surface canonical definition):

- **(a) MMU model.** Models the 32-page MMU at ports `0x70+slot / 0x74` matching MicroBeast hardware. Writes to `0x70 / 0x71 / 0x72 / 0x73` select which 16 KiB page is mapped into slots 0 / 1 / 2 / 3 respectively; `0x74` carries the global mapping enable. Verify against `docs/antforth-banking-redesign.md` §5.1.
- **(b) Pipe-able.** Accepts stdin-fed Forth source over the CP/M 2.2 console BDOS calls (functions 1, 2, 6, 9, 10), produces deterministic stdout capture, and exits cleanly on `BYE` (CP/M warm-boot) without requiring an interactive UI. Match the iz-cpm invocation shape: `printf '<probe>\r\nBYE\r\n' | <emulator> <flags> <target.com> 2>/dev/null`.
- **(c) Bank-visibility for tests.** Test scripts can assert which logical / physical bank is currently active in slot 1 / slot 2. Acceptable mechanisms: emulator-side port-trace mode, OR Forth-side readback via `IN A, (0x71)` returning the last-written page index.

A candidate passes only if all three criteria are PASS (no waived criteria). Story 16.3 AC2 captures the fallback path (SCP via `/bmad-bmm-correct-course`) if zero candidates pass.

## 3. Pick rationale

`iz-cpm-banking` is the only candidate that satisfies all three pinned criteria as-shipped, with no waivers, ports, patches, or wrappers needed for any criterion. Key supporting facts:

- **Criterion (a) — built in.** The fork's `src/cpm_machine.rs` implements the MicroBeast MMU port layout verbatim: `PORT_BANK0 = 0x70`, `PORT_BANK3 = 0x73`, `PORT_MAP_ENABLE = 0x74`, 64 virtual banks (32 Flash `0x00`–`0x1F` + 32 RAM `0x20`–`0x3F`), 16 KiB bank size, `0x3F` mask on bank-select values — exactly matching `docs/antforth-banking-redesign.md` §5.1. The fork's reset state (mapping enabled, RAM banks 32–35 in slots 0–3) is deliberately tuned for CP/M 2.2 backward compatibility, preserving the upstream iz-cpm 975-PASS baseline (verified — see (b) below). The fork ships eight Rust unit tests exercising the MMU (`default_mapping_targets_first_64k_of_ram`, `disable_mapping_exposes_flash_banks_0_to_3`, `remapping_a_physical_bank_points_at_a_different_ram_bank`, `bank_register_is_masked_to_six_bits`, `writes_to_flash_through_mapping_are_ignored`, `mapping_enable_register_round_trips`, `load_flash_makes_image_visible_through_mapping`, `load_flash_rejects_oversized_images`) — all PASS on `cargo test --release` at dev-pass time.
- **Criterion (b) — inherited from upstream.** The fork is a thin extension over upstream `ivanizag/iz-cpm`; the CP/M 2.2 console BDOS plumbing (functions 1, 2, 6, 9, 10) and `BYE` warm-boot exit are byte-identical to upstream. Running the full antforth REPL test suite (`make test-repl` with the fork's binary in place of the installed upstream iz-cpm) reproduces **975 PASS / 0 FAIL / 2 SKIP** byte-identical to upstream — zero behavioral drift on any non-MMU code path.
- **Criterion (c) — Forth-side readback.** The fork's `port_in` implements MMU register reads: `IN A, (0x71)` returns the current value of `bank_map[1]`, etc., and `IN A, (0x74)` returns the mapping-enable bit. This satisfies the Forth-side-readback path for criterion (c) directly — no emulator-side port-trace mode needed (though such a mode could be added trivially via `--dump`-style instrumentation per commit `1777a85`'s precedent if future probes want sidecar capture).

The fork ships an additional `--dump <basename>` CLI arg + port `0x80` write-to-dump mechanism (commit `1777a85`) for debugging — not used by Story 16.3's first iron probe but documented here for completeness; future Epic 17+ probes may use it.
