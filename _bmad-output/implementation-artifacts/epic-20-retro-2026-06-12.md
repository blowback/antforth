## Headline

Epic 20 delivered the bank-aware lookup surface — `FIND` and `WORDS` traverse banks invisibly while the everyday FORTH-wordlist lookup incurs **no MMU switch**. The metric line is "3 stories, +680 B, 0 regressions, full HW ledger, v3.0.5." The **real** story is that the planned mechanism (per-wordlist `bank` field) was investigated, found unworkable, and replaced mid-flight — project-lead-steered — with **inline 24-bit fat dictionary pointers** `[addr:2][bank:1]`. That substitution did more than deliver FIND/WORDS: it **abolished** the lookup-path bucket-chain aliasing class that Epic 19.5 only **contained** (carried debt A2 from the last retro). The cost was a header-format migration whose +680 B blew 3.4× past the ~200 B envelope — accepted as a one-off design substitution, not a calibration miss to chase.

## What went well

1. **The mid-flight design substitution was the decisive move — and project-lead-steered.** The planned per-wordlist `bank` field cannot describe antforth's single global wordlist (entries scattered across many banks; wordlist structs live in the `$8000` window → unreadable when another bank is mapped). Ant steered it to inline 24-bit fat pointers: the bank travels *with* each pointer, so the global wordlist is genuinely global, name+body stay in-bank (frugal on fixed memory), and the fixed-address fast path takes no MMU op. The 975 baseline held byte-for-byte.
2. **It abolished a carried-debt class, not just shipped a feature.** Epic 19.5's challenge #2 / action A2 was the unguarded lookup-path bucket-chain aliasing variant. Epic 20's fat-pointer FIND **abolishes** it (page-in before deref of any window-resident address) rather than containing it. Predicted in the 19.5 retro; delivered.
3. **POC-before-commit.** The fat-pointer layout was proven with a throwaway parallel-array POC first, *then* implemented as the chosen inline-uniform layout. The header-format migration was de-risked before the 379-link rewrite.
4. **Adversarial CR earned its keep.** The bank-removal scrub defect — removing the old `current_bank>0` bucket-skip linked bank-N entries into the shared buckets, but `-BANK`/`BANKS-CLEAR` didn't scrub them, leaving stale window fat-pointers a later FIND/WORDS would page in as garbage — is a silent-corruption bug the happy path never reaches. Caught in CR, fixed with `scrub_forth_buckets`, HW-re-verified.
5. **Honest scope reconciliation over dead weight.** 20.2 found the planned FR-P4-30 (source-bank error attribution) had lost its referent under the new mechanism (no per-bank wordlists; a FIND miss now means "absent everywhere") and **retired it with a recorded rationale** instead of building it. 20.3 recorded the +680 B breach as an explicit SCP re-baseline (`sprint-change-proposal-2026-06-12.md`), not a buried acceptance.

## What didn't — challenges

1. **The envelope prediction was wrong on an axis the calibration doesn't model.** Last retro's action A5 said "plan Epic 20 at ~2.4–2.7× the ~200 B target (pure-addition, no retirements)" → would have predicted ~480–540 B. The actual +680 B came from a design **substitution** (localised FIND tweak → full header-format migration: +1 B × ~379 kernel links + 64 B bucket array + walk/build code + name buffer), not a same-design overshoot. **A5 was followed and still missed** — because the multiplier calibrates overshoot *of a fixed design*, and says nothing when the design itself changes.
2. **"0-byte / verification-only" stories grew under CR.** 20.1 reported 27516 B; its *own* CR pass silently grew it to ~27625 (bank-aware WORDS add-on + fat-bank-byte error recovery + label-record zeroing). That made 20.2 — planned 0 B — a pure verification of code that had shipped in 20.1's CR, and its "WORDS not yet — Story 20.2" note was stale against its own CR fixes. The story-text byte figures drifted from the artifact repeatedly (20.2's AC8 had to warn "do NOT inherit 20.1's stale 27516 B").
3. **The version slug was stale drift end-to-end.** Every Epic 20 filename and the epics-file placeholder read "3.x.4," but v3.0.4 was consumed by the 19.5 interlude. Caught at 20.3 *draft* (not dev-pass, which is the win), but it's the recurring smell flagged before: the `3.x.N` planning slugs are never the source of truth for the version number and keep needing reconciliation at close-out.

## Key takeaways

1. **A mechanism substitution voids the byte multiplier.** The 2.4× calibration models overshoot of a *fixed* design; when the design itself changes from the planning premise, re-derive the budget from the new cost class. Epic 20 = one-off substitution; Epic 21 reverts to the multiplier.
2. **Abolish beats contain.** The fat-pointer FIND didn't just ship a feature — it retired the lookup-path aliasing class that 19.5 could only guard. Picking the mechanism that *removes* a debt class is worth a one-time structural cost.
3. **Retire dead requirements honestly.** FR-P4-30 lost its referent under the new mechanism; retiring it with a recorded rationale beat building it for completeness.
4. **CR keeps finding the silent-corruption path the happy path can't reach** — every pass, across 19.5 and 20. The adversarial review is load-bearing, not ceremony.
5. **The slug is never the version.** `3.x.N` planning placeholders drift; re-validate the version surface from source-of-truth at every close-out.
