## What went well

1. **ADR-first root-cause (the decisive move).** Story 19.5.0 correctly identified DR-1 as *portal-window dictionary aliasing* (a body above `$8000` that later does `BANK!` aliases its fetch cells into the foreign page → reads `$0000` → warm boot), killing the false "trampoline fragility / kernel-size trigger" model with evidence (relative-shift invariance, flat-`iz-cpm` cross-check). It also retired the H-A sentinel-collision and H-B emulator-bug hypotheses. One spike instead of more reverts.
2. **Option C — retire, don't patch.** The self-dispatching `RST $28` stub (≈−13 B net, **0 T per non-stub NEXT step**) retired the fragile `EXIT_CODE` sentinel *and* the `cross_bank_return` trampoline, folded `w_EXECUTE_cf` from 77 B to 4 B, and fixed **both** Epic-19 root causes with one uniform 2-cell-frame + `xbank_thunk` return (DOCOL, DOVAR, DOCON, code-words all return identically). The architecture funded its own additions — the reason the envelope came in at 1.2×.
3. **Self-calibrating regression harness (F3).** The straddle sweep derives its pad sizes from runtime `HERE U.` output every run. Layout shifted under it on nearly every byte added this epic; it absorbed all of it (3/3 throughout, one verified trip at a K=16 insertion, source-restored green). Absolute-address anchors would have cried wolf repeatedly.
4. **Adversarial CR earned its keep, every pass.** 19.5.1 found 3 real defects in 12 candidates; 19.5.2 found **CR-F1** — THROW's caught path restored MMU + `current_bank` but not the live HERE/LATEST/wordlist_head triple, so a real `BANK!` between CATCH and THROW left the catcher compiling into a foreign dictionary (sticky on a second same-bank `BANK!`). A four-step silent-corruption bug the happy path can't reach. Fixed via `triple_owner` + frame +9 + `bank_triple_swap`; witnessed by probe-19.5.2-d.
5. **Byte-estimate discipline (B.2).** Per-component itemisation caught an 8× planning under-estimate on option A (missed the 320-site multiplier) and kept every quoted figure re-derived rather than cited.

## What didn't — challenges

1. **The epic exists because of a two-story misdiagnosis.** Epics 19.2/19.3 reverted on a "trampoline/kernel-size fragility" theory that was written into memory and later **superseded** — size only moved *where* bodies straddle `$8000`; the straddle was the variable, not the size. A correlation was chased.
2. **A second aliasing variant surfaced mid-pass.** 19.5.1 AC5b exposed *lookup-path* aliasing (bucket-chain pollution): shared hash buckets accumulate window-resident entries; FIND walking such a chain while a foreign bank is mapped strands the interpreter at `-13`. Distinct from the threading-path DR-1; forced behavioural witnesses into isolated kernel-only fixtures. **Currently unguarded — lands squarely in Epic 20's scope.**
3. **Planning cadence put HW investigation in the wrong story.** The plan named 19.5.4; the HW UAT actually ran during 19.5.2's smoke (and that's where DIV-1 was found), making 19.5.4 a transcription/close-out story. Signal: *HW investigation gravitates to the first story whose smoke exposes the behaviour.*
4. **DIV-1 — the emulator was more correct than the hardware.** `IN A,(0x72)` MMU-slot readback was concluded to float on real silicon (the emulator models it; `cpm_machine.rs:138`). The original `+BANK` restore re-installed an unmapped page, killing the window until the first explicit `BANK!`. The kernel had trusted a docstring claim of silicon parity that was never HW-verified. **Project lead has flagged the diagnosis for independent confirmation** (see action A1).
5. **Envelope still ran slightly over** (119 vs ~100 B), driven by two unbudgeted correctness fixes (CR-F1 triple-restore; DIV-1 +13 B). Honest reconciliation: ≈106 B excluding the DIV-1 correctness fix — within rounding.

## Next epic — Epic 20: Bank-aware FIND + WORDS + attribution (ships antforth 3.x.4)

Epic 20 makes `FIND`/`WORDS` traverse banks invisibly (system wordlists tagged `bank=fixed` so the everyday case incurs no MMU switch), with lookup-failure messages naming the source bank. 3 stories, ~200 B target.

**Critical dependency / significant discovery:** Epic 20 **abolishes** the portal-aliasing class that Epic 19.5 only **contained**. The unguarded *lookup-path* bucket-chain aliasing variant (challenge #2) lands directly in Story 20.1's `FIND` traversal. This is not a plan invalidation — Epic 20 already targets bank-aware FIND — but the bucket-chain mechanism must be an **explicit named AC + risk** before 20.1 dev-pass (project lead: *"needs a planning touch first"*).

**Dependency on DIV-1 understanding:** Epic 20 leans on slot-2 mapping correctness. The DIV-1 silicon re-check (A1) should land before 20.1 commits, so Epic 20 builds on a correctly-understood hardware model.

## Key takeaways

1. **ADR-first on a fragility class prevents chasing the wrong defect** — root-cause before code.
2. **Retire, don't patch.** Option C's sentinel + trampoline retirements both fixed the bug class *and* paid for the additions (1.2× envelope vs the 2.4–3.1× norm).
3. **Never trust a port readback whose docstring was never HW-verified** — emulator agreement is not silicon evidence (DIV-1).
4. **Self-calibrating test geometry beats absolute anchors** under a moving dictionary layout.
5. **The subsystem turned the corner.** A nearly-abandoned feature is now under control — worth recording as the epic's real outcome.
