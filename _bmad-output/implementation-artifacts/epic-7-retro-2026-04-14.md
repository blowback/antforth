## Successes

- **Convention established and held across 13 words** — 7.1 proved EXX safe in the AntForth environment; 7.2 and 7.3 extended the pattern to 5 more words without deviation. Leaf-level rule ("don't call anything that also EXXes") held trivially throughout — no nested EXX sites emerged.
- **Story 7.2 eliminated three scratch variables entirely** — `.recog_save_ip`, `.recog_len`, `.recog_name` (5 bytes of data) deleted outright. The recognizer went from memory-load-heavy to register-resident. Code review on top found an additional −11 bytes by merging the `.recog_no_match` and `.recog_fast_false` tails via fall-through.
- **Story 7.3 NUMBER? insight generalises** — the shadow BC' register acts as a free one-exit TOS-preservation slot for any `( x -- ... )` word that needs the original x on a failure/reject path. Eliminated the explicit `PUSH BC / POP BC` bracket. Same idea applied to the M1 PAREN review fix.
- **Estimates much closer than Epic 6** — Epic 6's 6.3 overshot by 303%; Epic 7's stories landed within 26%–167% of estimate, with 7.3 actually inside its stated range. The shift from "count assumed instruction bytes" to "count actual Z80 opcodes" from Epic 6's action item is visibly paying off.
- **Code reviews continue to earn their keep** — every story had findings; 7.1's review caught a pre-existing `INC IX` bug in `w_QUERY_cf` (misaligned return stack by +1 byte per QUERY, masked by QUIT's RP! reset). Epic-7-internal bug hunt as a byproduct of unrelated review.
- **Zero regressions, zero new tech debt, zero production incidents** across all 3 stories. Manually verified on MicroBeast hardware at every stage.

## Challenges

### 1. Story 7.2 Overshot Estimate by 2.7×

Estimate 10–15 bytes, actual 40 bytes. Root cause: the estimate counted only the direct save/restore replacement; the actual savings came largely from **eliminating three scratch memory variables and their associated loads/stores**, plus a review-time tail-merge opportunity nobody predicted. This is the inverse of an estimation problem — we *underestimated* the compounding effect of register liberation.

**Lesson:** When EXX frees registers, the second-order savings (eliminated scratch variables, simplified exit paths, mergeable tails) can exceed the first-order save/restore savings. Budget for this on future register-liberation work.

### 2. Ongoing Register-Contract Bookkeeping

Epic 7 introduced a new invariant — the leaf-level rule — that developers must carry in their head when writing CODE words. This is one more item on the Z80 mental-stack alongside "BC=TOS, DE=IP, don't clobber DE, …". So far there's only one class of enforcement: grep for EXX usage before adding a CALL inside an EXX word. No automated guard exists.

**Not an action item yet** — the convention is young enough that human review catches it, and it's documented in each story's Dev Notes. Flag if a future story inadvertently nests EXX.

### 3. EXX Vein Partially Tapped

Epic 7 converted all in-scope candidates. Remaining `CALL rpush_de/rpop_de/rpush_bc/rpop_bc` sites:

- `src/formatting.asm` — 11 sites in the `.` / `U.` / `.R` / `.S` print pipeline. **Explicitly out of scope** per epic spec (BC used for values, DE as scratch throughout — full restructure required).
- `src/strings.asm:167,252` — `CHAR` (parse token, push char value)
- `src/compiler.asm:689` — `(;CODE)` / DOES> runtime exit
- `src/system.asm:120` — `ABORT"` runtime
- `src/control_flow.asm:207` — `(DO)` runtime
- `src/outer_interpreter.asm:99–127` — the INTERPRET loop itself (likely should stay — it *is* the main thread)

Rough unconverted-byte estimate (excluding formatting and INTERPRET): ~30–50 bytes recoverable. **Documented, not committed.** Project lead flagged Epic 7 as a natural pause point.

Additionally: **AF'/EX AF,AF' is entirely unused** in the codebase. No word currently needs to preserve A/flags across a subroutine boundary that couldn't also be satisfied by EXX-style reasoning, but this is another dormant resource.

## Key Insights

1. **"A survives EXX" is the canonical micro-pattern.** Applied consistently in 7.2 (recognizer match/no-match exits) and 7.3 (ACCEPT, >NUMBER, NUMBER? ok-path before the M2 simplification). When a word needs to compute a value *inside* an EXX region and emit it as new TOS: stage it through A across the exit EXX, then rebuild BC from A in the restored main set. This is now the project's standard idiom for EXX-region exit construction.

2. **Register liberation has compounding second-order savings.** Converting save/restore to EXX saved ~5 bytes per word on paper; in 7.2 it saved 40 because the freed registers eliminated three scratch memory variables and made tail-merging possible. When a refactor frees a register, budget time to audit what memory spills and contortions that register's absence was causing.

3. **Shadow BC' is a free one-exit TOS-preservation slot.** For any `( x -- ... )` word that needs the original x on exactly one exit path (typically a failure/reject path), the entry EXX parks x in BC' automatically. No explicit PUSH BC / POP BC needed. NUMBER? used this to eliminate a PUSH/POP pair; the M1 PAREN review fix applied the same pattern.

4. **Estimation improved meaningfully after Epic 6's retro action.** Epic 6 max variance: +303% (story 6.3). Epic 7 max variance: +167% (story 7.2) — and that overshoot was *upside*. Counting real opcode bytes instead of assumed bytes is the difference.

5. **Adversarial review remains load-bearing.** 7.1's review caught a latent `INC IX` bug in an unrelated word that had been there since the Epic 6 rpop_bc refactor. 7.2's review found −11 bytes of tail-merging the dev agent missed. 7.3's review found −3 more bytes (M1+M2). Every story: findings. Holding pattern confirmed.
