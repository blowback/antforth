## Story

As a BMad Method workflow author and dev agent operator,
I want the in-pass adversarial review step removed (or skip-branched) from the quick-dev workflow tree, the create-story AC pattern, and the story-template prompts; reconciled with the `CR` command's fresh-context external-review semantics; documented in retro and memory,
So that future story dev-passes structurally cannot re-introduce the in-pass review anti-pattern that surfaced as F-Retro-1 across all eleven post-Epic-2 epics.

This is the first story in Epic 13.5 (Phase-2 Cleanup Slate) — the process-recovery vehicle that gates `antforth 2.0`. It carries zero feature scope; it makes the rest of the slate's S1 standing commitment ("adversarial review continues — but fresh-context external pass via `CR` command, not in-pass") **structurally enforceable** rather than convention-only. PD-1 closing is the precondition for any 13.5.1..13.5.6 dev-pass starting (per Epic 13.5 §"Sequencing").

---

## Severity Re-Statement (BINDING — context for every dev-pass decision)

This story has zero kernel impact and zero binary delta. The severity statement here is *process*, not *runtime*: every story dev-pass since Epic 3 (`bmad-bmm-dev-story` adopted) has run an in-pass adversarial review even though codified intent said external-only. The cost was hidden by the discipline yielding findings on every story (eleventh consecutive epic per Epic 13 retro). The cost surfaces structurally:

| Layer | Says | Behaviour |
|---|---|---|
| **Memory** (`feedback_adversarial_review.md`) | "Reviews MUST find things; absence of findings is suspect. Reviews are adversarial by design." | Codified intent expressing the *what* |
| **Dev-agent definition** (`_bmad/bmm/agents/dev.md:64`) | `CR` command — "use a fresh context and a different quality LLM if available" | Codified intent expressing the *where* (external) |
| **Workflow tree** (`_bmad/bmm/workflows/bmad-quick-flow/quick-dev/steps/step-05-adversarial-review.md`) | Mandatory Step 5 with hard-coded `nextStepFile`; failure-mode list literally includes "Accepting zero findings without questioning" | Convention drift in workflow runtime |
| **Story templates** (every Story 13.x AC) | "trigger an adversarial review pass per `feedback_adversarial_review.md`" | Convention drift in story drafting |

**Lesson 13-A (codified):** when memory or party-mode says "stop X" and the BMAD workflow tree still requires X as a step, X happens. The fix lives in workflow files + templates, not in memory or instructions.

**The dev agent followed instructions — the wrong stack.** PD-1 closes the gap at the structural layer (workflow tree + templates), making the codified intent enforceable rather than aspirational.
