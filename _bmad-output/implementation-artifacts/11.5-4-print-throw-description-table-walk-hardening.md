## Story

As an antforth maintainer,
I want the description-table walk in `print_throw_description` to use a 16-bit `ADD HL, <length>` form rather than the current 8-bit `ADD A, L / JR NC / INC H` carry pattern,
so that the walk does not wrap if the kernel grows past 32 KB and the `throw_desc_table` relocates near the top of memory — closes Story 11.5 F9 / Story 11.6 R-L6 carry per `epics.md:1017-1035`.

## Dev Notes

### Bug summary

`print_throw_description` (`src/exception.asm:482-545`) walks `throw_desc_table` linearly looking for a matching THROW code. Each table entry is `<DW code, DB len, DB text...>`. The walk advances past a non-matching entry by:

```
.ptd_skip:
        LD      A, (HL)         ; A = length
        INC     HL              ; HL → first text byte
        ADD     A, L            ; carry in low byte of HL
        LD      L, A
        JR      NC, .ptd_loop   ; no carry — advance complete
        INC     H               ; carry into high byte
        JR      .ptd_loop
```

The 8-bit `ADD A, L / JR NC / INC H` carry pattern is wrap-safe across a single 16-bit arithmetic step **as long as `INC H` does not wrap from $FF to $00** — i.e., as long as the table never starts at or past $FF00. Today the table sits at $412C in a 17,520-byte binary that ends near $4570, so wrap is impossible. But Phase-2 (Epics 12–13: search-order wordlists + file-access) will grow the binary past 32 KB; if the table relocates near the top of memory, the 8-bit walk would silently wrap and produce undefined behaviour.

The fix swaps the 8-bit pattern for a 16-bit `ADD HL, <length>` form. Two viable Z80 idioms (per AC #3):
- **(a)** Retain `LD A, (HL); INC HL`; replace `ADD A, L / LD L, A / JR NC / INC H` with `LD E, A; LD D, 0; ADD HL, DE`. 8 bytes total (1 saved).
- **(b)** Replace the entire chain with `LD E, (HL); INC HL; LD D, 0; ADD HL, DE`. 7 bytes total (2 saved). Recommended for fewest bytes and simplest read.

The Z80's `ADD HL, DE` instruction does the 16-bit add modulo 65536 — wrap is harmless because the next loop iteration's terminator-check (`LD A, D / OR E / RET Z`) tests against the table itself; if HL has wrapped to garbage memory, the eventual mismatch terminates with a benign "no description printed" outcome (which matches the existing miss path).

### Fix locus

A single block of 9 bytes at `src/exception.asm:537-545` (runtime address $411B in the post-Story-11.5.3 build). The comment block at `:482-507` is also updated to reflect the post-fix reality and remove the 32-KB-relocation conditional.

### Why this story matters now (not deferred to Phase-2)

Two reasons per `epics.md` Epic 11.5 intro:

1. **Stabilisation before Epic 12.** Epic 11.5 is a debt-cleanup interlude; addressing the F9 / R-L6 carry deferral before Epic 12 starts means the table-walk has been audited and hardened **before** Epic 12 grows the kernel and exposes the latent wrap. Catching the wrap post-hoc (during Epic 12 dev) would conflate the table-walk fix with whatever Epic 12 work triggered the symptom.

2. **Cheap to do.** A one-form swap with near-zero binary delta and zero behavioural change. Deferring it to Phase-2 would require re-loading the same context months later for a 7-byte edit.
